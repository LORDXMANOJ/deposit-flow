# The 20 UX details

Status of each detail in DepositFlow. Paths are relative to the project root.

| # | Detail | Status | What and where | How to see it |
|---|---|---|---|---|
| 1 | Skeleton loaders | Built | `PageSkeleton`, `TableSkeleton` and `StatStrip loading` in `src/components/ui.tsx` reuse the real table and KPI markup; `src/app/(app)/loading.tsx`; `.delayed-reveal` in `src/app/ux.css` keeps them invisible for the first 300 ms | DevTools > Network > Slow 3G, then move between pages |
| 2 | Optimistic updates | Built | `useOptimistic` in `src/components/notifications.tsx` (mark read) and `src/components/alert-list.tsx` (acknowledge, resolve), rolled back with an error toast if the server refuses. Not used for releases or anything involving money | Run checks, then acknowledge an alert or mark a notification read |
| 3 | Command menu | Built | `src/components/command-menu.tsx`: every page, the main actions and a scoped record search (`/api/search`); arrows, Enter and Esc only | Ctrl+K or ⌘K, or `/` |
| 4 | Shortcut hints | Built | `src/components/shortcuts.tsx` shows ⌘ on Apple devices and Ctrl elsewhere; hints in the command menu, sidebar hover and collapsed-sidebar tooltips; `g` + letter navigation and `[` for the sidebar; ignored while typing in a field | Hover a sidebar item; press `g` then `f` |
| 5 | Undo toasts | Built | `src/components/toast.tsx` (`role="status"`, 8 s, pauses on hover); used for archive/restore (`archive-toggle.tsx`) and alert acknowledge/resolve. Permanent delete and financial decisions keep a confirm dialog because they cannot be undone | Archive an institution, then press Undo |
| 6 | Stale-while-revalidate | Built | `src/components/use-swr.ts`: cache in memory and sessionStorage, refetch on focus, on reconnect and every 60 s; used only for notifications. Financial figures are always rendered fresh on the server | Open the bell, switch tabs and come back |
| 7 | Prerendering | Built | Speculation rules with `eagerness: "moderate"` in `src/app/layout.tsx`, excluding `/api/*`, `/login`, downloads and `[data-no-prerender]`; sign-out is a POST form, never a link. Next's own prefetch only fetches the loading boundary for these dynamic pages, so this adds full prerender on hover. Chromium only | DevTools > Application > Speculative loads, hover a nav link |
| 8 | BlurHash placeholders | Skipped | Uploads are mostly PDFs and images are never shown in galleries or grids. It would need a server-side image decoder dependency for a placeholder nobody would see | |
| 9 | View transitions | Built, partly | `document.startViewTransition` for the theme switch (`toggleTheme` in `src/components/shell.tsx`); `@view-transition { navigation: auto; }` and a shared `view-transition-name` on page titles in `src/app/ux.css`. Next's client-side navigation does not fire cross-document transitions without an experimental flag, so in-app page changes use a 220 ms CSS arrival (`src/app/(app)/template.tsx`) instead | Toggle dark mode; move between pages |
| 10 | Swipe-to-dismiss sheets | Built | `src/components/sheet.tsx`, written without Vaul: follows the finger, closes past 30 % of its height or on a flick faster than 0.5 px/ms, rubber-bands upward, keeps a close button and Esc | Phone width (390 px), open the bell, drag the sheet down |
| 11 | Interruptible animations | Built, partly | Sheet, drawers and scrims animate `transform`/`opacity` with transitions, which restart from the current position when interrupted; no keyframes on anything a user can interrupt; input is never blocked. They are not velocity-carrying springs (that would need the Motion library) | Open and close the phone menu quickly |
| 12 | Predictive back | Skipped | Android native API; this is a web app | |
| 13 | Hit slop | Built | `@media (pointer: coarse)` in `src/app/ux.css`: 44 px minimum on buttons and nav items, and `.hit::after` enlarges small icon buttons without moving neighbours | Touch device or device emulation |
| 14 | Safe-area insets | Built | `viewportFit: "cover"` in `src/app/layout.tsx`; `.safe-top`, `.safe-bottom`, `.safe-x` with `env(safe-area-inset-*)` on the header, drawer, sheet, toasts and page padding | iPhone emulation in DevTools |
| 15 | One-time-code autofill | Skipped | There is no OTP sign-in; the demo uses a role picker and there is no SMS backend | |
| 16 | Tabular numbers | Built | `font-variant-numeric: tabular-nums` on table cells, KPI figures, badges, inputs and every `.figure`/`.mono` (`src/app/globals.css`, `src/app/ux.css`) | Amount columns line up in every table |
| 17 | Balanced headlines | Built | `text-wrap: balance` on headings, `text-wrap: pretty` on paragraphs (`src/app/ux.css`) | Narrow the window on the landing page |
| 18 | Continuous corners | Built | `corner-shape: squircle` inside `@supports` for cards, buttons, inputs, sheets and dialogs (`src/app/ux.css`); other browsers keep the border radius | Chromium with corner-shape support |
| 19 | Idempotency keys | Built | `useIdempotencyKey` (`src/components/forms.tsx`) creates a UUID per create attempt; `withIdempotency` (`src/lib/idempotency.ts`) plus the `idempotency_keys` table replays the first result; `POST /api/v1/deposits` accepts an `Idempotency-Key` header. Submit buttons are disabled while a request runs. Server actions cannot set headers, so in-app forms send the key in the payload. Covered by 3 tests | Double-submit a new deposit: one record is created |
| 20 | Safe triangle | Skipped | The app has no hover menus with submenus; all menus open on click | |

Every animation above is disabled or reduced to a cross-fade under `prefers-reduced-motion`. Typecheck ran after each batch of work and the tests at the end (53 passing); the details were built as part of each page rather than one commit per detail, so the checks ran per batch, not after every single item.
